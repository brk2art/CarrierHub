# CarrierHub: rules for coding agents

CarrierHub is a .NET 10 system that integrates unreliable carrier APIs and serves merchants through a versioned
public API, signed webhooks and an AI ops assistant. It runs locally with .NET Aspire and in Azure Container Apps
with azd and Bicep. The repo is public.

## Who owns what
- `src/CarrierHub.Tracking`: shipments, their timeline and claims. The ONLY service that touches `trackingdb`.
  Publishes shipment events through a transactional outbox.
- `src/CarrierHub.Notification`: delivers shipment events to merchants' webhook URLs. Owns `notificationdb`.
- `src/CarrierHub.PublicApi`: the merchant-facing API (`/v1/...`). Reaches shipment data only through Tracking.
- `src/CarrierHub.CarrierGateway`: talks to the carriers, deduplicates with Redis, forwards carrier events to
  Tracking through Service Bus (queue `carrier-events`, one session per shipment).
- `src/CarrierHub.MockCarriers`: simulated carriers (NordPost, FastShip, ParcelGo) with switchable faults.
- `src/CarrierHub.OpsAssistant`: the AI assistant (Microsoft Agent Framework, Microsoft.Extensions.AI, Azure
  OpenAI, AI Search, Content Safety). Reads shipment data ONLY through the Public API with the caller's token.
  Owns `assistantdb` (conversations, pending actions, sweep decisions). Also runs as the `sweep` job
  (`--sweep-once`).
- `src/CarrierHub.OpsAssistant.Web`: the React + TypeScript chat page, built into OpsAssistant's `wwwroot`.
- `src/CarrierHub.CalendarMcp`: an MCP server (public holidays, working days) the assistant calls.
- `src/CarrierHub.McpHttp`, `src/CarrierHub.McpServer`, `src/CarrierHub.PolicyIndexer`: local only, never deployed.
- `src/CarrierHub.AppHost`: the Aspire AppHost, the single description of the system (local and Azure).
- `src/CarrierHub.ServiceDefaults`: telemetry, health checks and shared defaults for every service.
- `labs/`: experiments. Don't change them unless asked.

## Build and test
- Build: `dotnet build`
- Test: `dotnet test` (Docker Desktop must be running: the Tracking tests use Testcontainers)
- Run locally: `dotnet run --project src/CarrierHub.AppHost`
- A change is done only when `dotnet build` has 0 warnings and `dotnet test` passes.
- The evaluation suite (`tests/CarrierHub.OpsAssistant.Evals`) calls Azure OpenAI and costs real money:
  never run it without asking first.

## Rules that must never break
- Never put a secret in the repo: keys, passwords, tokens, client secrets and connection strings with passwords
  live in user secrets locally and in azd parameters in Azure. Never print or log them. Why: the repo is public.
- Azure services are reached with managed identity, never keys. Code uses a key only when one is configured
  (local) and DefaultAzureCredential otherwise.
- Every AI endpoint checks the caller (the `/v1/me` filter on the `/v1/assistant` group) before any model call.
  Why: a fake token must never spend Azure OpenAI tokens ("denial of wallet").
- Development tokens (`dotnet user-jwts`) are never accepted in Production. Production without Entra settings
  must refuse to start.
- The assistant never opens a claim: it only proposes, and a person approves with their own token.
- Each service owns its database; no service reads another's.
- Sweeps, A2A and AG-UI endpoints are mapped in Development only (A2A and AG-UI have no sign-in yet).
- Readiness checks contain only what a service can't work without; liveness checks contain nothing external.

## Infrastructure
- `infra/` and `src/CarrierHub.AppHost/infra/` are generated by `azd infra gen` from the AppHost. Never edit them
  by hand: change the AppHost, then regenerate from scratch
  (`Remove-Item -Recurse infra, src/CarrierHub.AppHost/infra; azd infra gen`) and review the `git diff`.
- Before committing generated files, check every new value is a placeholder (`securedParameter`, `.Env`, a Bicep
  param), never a real secret.
- `ops/` is hand-written: `budget.bicep` (subscription budget), `alerts.bicep` (P95 alert, included by the
  AppHost), `grant-sweep-role.ps1` (postprovision hook).
- Never run `azd up`, `azd deploy`, `azd provision` or `azd down` without asking: they create or delete paid
  resources. After every session the environment is torn down with `azd down --purge`.

## Conventions
- .NET 10, C#, minimal APIs, ServiceDefaults in every service.
- Keep package versions matched: all Aspire packages on the same version (13.6.5), all EF Core and ASP.NET Core
  packages on the same version.
- Comments explain why, not what.
- EF Core migrations: add them with `dotnet ef migrations add`; never edit a generated migration or its snapshot.

## Windows and PowerShell
- Use PowerShell 7 (`pwsh`). Windows PowerShell 5.1 breaks JSON quoting for native commands and has no `&&`.
- On Windows `az` is a batch file: parentheses in an `--query` or KQL argument break it. Put the query in a file
  and pass `@file`, or avoid parentheses.
- `dotnet run` applies `launchSettings.json`; use `--no-launch-profile` to really run as Production.

## How to work with me
- For anything bigger than a small fix, propose a short plan first and wait for my OK.
- Work in small steps. After each step, run the build and the tests, and summarise the diff.
- Never commit or push without asking. Never run commands that cost money or touch Azure without asking.
- Don't add a package without saying why.
